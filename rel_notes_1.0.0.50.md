# Workspace 1C 1.0.0.50

Дата выпуска: **2026-10-22**. Релиз доступен для **Windows** (WPF) и **Linux** (Avalonia).

## Исправлено

- **Устранён рост памяти при переключении вкладок «Все / Избранное / Недавние» на Windows:
  сброс Recycling-пула контейнеров теперь выполняется синхронно на каждой смене вкладки,
  heapAfterGcMb стабилизируется (1.0.0.50, issue #21, Windows и Linux)**:
  - по логу `CM_TREESWITCH` с версии 1.0.0.46 видно, что `flushPanels=0` в **каждой** записи
    серии: отложенный вызов сброса (в 1.0.0.46 — `DispatcherPriority.Background`) не доживал
    до простоя очереди при быстрой серии переключений, а демпфер не позволял запланировать
    его повторно — Recycling-пул `ItemContainerGenerator` ни разу не разбирался за серию;
  - рециклированные контейнеры строк (сложные шаблоны с кистями, кнопками, иконками
    MaterialDesign) копились в пуле вложенных ItemsControl: живой рост `heapAfterGcMb`
    ~3–4 МБ/смену (29 → 347 МБ за ~65 переключений), не возвращавшийся после `GC.Collect(2)`
    (пул генератора — сильный корень; при этом `allocMb=0`, `detach=0` — данные и узлы не
    при чём);
  - сброс `VirtualizationMode` Standard→Recycling выполняется теперь **немедленно** в
    обработчике `TreeRebuilt` (UI-поток) — очередь Recycler'а каждой панели разбирается за
    смену вкладки, старые контейнеры освобождаются сборщиком;
  - диагностика расширена: в `CM_TREESWITCH` добавлено поле `flushMs` (стоимость сброса,
    единицы-десятки мс), сбой сброса пишется в журнал с исключением (в 1.0.0.46 молчаливый
    `catch` прятал причину `flushPanels=0`);
  - закреплено юнит-тестами: постоянный плоский узел не детачится при сменах вкладок
    (`TotalDetachCount` не растёт), смена непересекающегося состава плоского узла порождает
    ровно один Reset коллекции Items при нуле событий корней.

Пожалуйста, установите 1.0.0.50 и подтвердите на своём стенде (Windows): включите флаг
`CM_TREESWITCH` в trace.json и прогоните ~30 переключений вкладок «Все/Избранное/Недавние» —
ожидается стабильный `heapAfterGcMb` без роста при `flushPanels>0` в каждой записи (кроме
первой после старта) и малом `flushMs`.
