# Workspace 1C 1.0.0.51

Дата выпуска: **2026-10-22**. Релиз доступен для **Windows** (WPF) и **Linux** (Avalonia).

## Добавлено

- **Миграция баз между кластерами 1С (1.0.0.51, issue #41, Windows и Linux)**:
  - в окне «Импорт из кластера 1С» появилась кнопка **«Мигрировать»** (тот же цвет,
    со стрелкой вправо) рядом с «Импортировать»; подпись под «Сервер 1С» сокращена,
    кнопка «Закрыть» отодвинута дальше и получила красную подсветку;
  - диалог миграции: выбор **сервера 1С назначения** из справочника «Серверы 1С»
    (сервер-источник в списке не показывается) и его кластера (единственный кластер
    выбирается автоматически), напоминание о количестве баз, поля «Пользователь СУБД»
    и «Пароль СУБД» (rac пароль СУБД не возвращает — вводятся для нового кластера),
    галочка **«Не удалять в старом»** (копия в другой кластер без удаления);
  - по «Перенести» для каждой базы: сначала база добавляется в новый кластер
    **с теми же данными, что в старом** (`infobase create`: имя, описание, СУБД,
    сервер и имя БД, локаль, уровень безопасности + учётные данные СУБД), затем,
    если галочка не отмечена, удаляется из старого кластера **без удаления БД**
    на сервере СУБД (`infobase drop` без `--drop-database`); фоном показывается
    прогресс «N из M: база»;
  - при успешном завершении — вопрос «Хотите заменить строку подключения?»: при
    ответе «Да» сервер и порт заменяются в базах списка приложения с совпадающим
    именем (Ref), окно импорта обновляет список баз кластера;
  - кнопка «Импорт» под базами в окне «Серверы 1С» переименована в
    «Импорт \ Миграция»; пункт меню «Операции» — в «Импорт \ миграция из кластера 1С…»;
  - поддержка rac 8.3.x и 8.5.x: используются существующие вызовы «cluster list»,
    «infobase summary list», «infobase create/drop» (перебор форматов идентификатора
    кластера для 8.5.x уже в RacClient); добавлены юнит-тесты (26 шт.).

Замена строки подключения применяется к списку приложения после закрытия окна
импорта. Обратите внимание: при переносе базы в другой кластер сервер 1С нового
кластера должен иметь доступ к той же базе данных на сервере СУБД (указывается
сервер и имя БД из старого кластера, а также пользователь/пароль СУБД).
