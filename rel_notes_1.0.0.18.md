# Workspace 1C 1.0.0.18

Дата выпуска: **2026-10-19**. Релиз доступен для **Windows** (WPF) и **Linux** (Avalonia).

## Исправлено

- **«Управление службами»: мгновенный Ctrl+ПКМ в трее (issue #11, Windows)** — клик
  с удерживаемым **Ctrl** по значку трея теперь **сразу** открывает меню служб (раньше
  приходилось держать Ctrl около секунды перед нажатием ПКМ, иначе показывалось штатное
  меню «как без Ctrl»). Контрол определяется нативно через `GetKeyState(VK_CONTROL)`
  (WPF `Keyboard.Modifiers` — только запасной вариант: в трее приложение без фокуса и
  модификаторы могут не отражать реальное состояние); штатное меню трея подавляется уже
  на `MouseDown`, до старта системного показа; кэш статусов служб прогревается при
  инициализации трея, а первый фоновый опрос происходит сразу (`dueTime` таймера — 0) —
  меню служб строится мгновенно даже сразу после запуска. Повторный Ctrl+ПКМ при уже
  открытом меню служб игнорируется (двойных меню нет). На **Linux** нативные треи
  (StatusNotifier/AppIndicator) не передают Ctrl+ПКМ — подменю «Службы» доступно из
  нативного меню (ограничение платформы).
- **«Управление службами»: экранирование `_` в WPF-меню служб (issue #11, Windows)** —
  имена служб/групп с символом `_` (например `S_DB`) в меню по хоткею «Меню служб»
  (Ctrl+Shift+Alt+S) и в меню «СЛУЖБЫ» окна монитора серверов теперь отображаются как
  есть: раньше WPF трактовал `_` в заголовке пункта как мнемонику (AccessKey) — символ
  пропадал, а следующая буква подчёркивалась. Добавлен чистый помощник
  `ServiceTrayMenuBuilder.EscapeMenuText` (удваивает каждый `_` — WPF показывает `__`
  как один `_` без мнемоники); применяется ко всем заголовкам служб/групп в
  WPF-адаптерах меню. В WinForms-трее мнемоника — `&`, в Avalonia `_` мнемоникой не
  считается — там изменения не требуются.

## Примечания

- Пункт про Ctrl+ПКМ в трее — только **Windows** (WPF): нативные треи Linux не передают
  Ctrl+ПКМ, поэтому на Linux меню служб открывается из нативного меню трея через подменю
  «Службы» (ограничение платформы, код не менялся).
- Экранирование `_` затрагивает обе платформы на уровне отображения, но правки внесены
  только в WPF-адаптеры меню (Avalonia `_` мнемоникой не считает).
- Issues #11 остаётся открытым до подтверждения пользователем.
