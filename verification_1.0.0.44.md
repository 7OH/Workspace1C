## Issue #36 — Заголовок окна свойств базы (1.0.0.37)

**Критерий готовности:** заголовок окна свойств базы содержит имя и обновляется при правке
«Наименования» (WPF + Avalonia).

- [ ] **Windows (WPF):** «Правка свойств базы» → в заголовке окна видно
      «Настройка информационной базы: Имя базы».
- [ ] **Windows (WPF):** меняем поле «Наименование» → заголовок окна обновляется сразу
      (превью), без нажатия «ОК».
- [ ] **Windows (WPF):** «Отмена» → изменения не сохраняются, заголовок главного окна прежний.
- [ ] **Linux (Avalonia):** те же проверки — заголовок с именем базы и живое обновление
      при правке «Наименования».

исчезают из всех подменю служб; флаги сохраняются в `services.json`.

- [ ] **Windows (WPF):** «Управление службами» → у строки-службы есть колонка-галочка

- [ ] **Windows (WPF):** перезапуск приложения → флаги сохранены (проверить `services.json`:

## Issue #21 — Рост памяти при переключении вкладок (1.0.0.41)

**Критерий готовности:** на Windows за 30 переключений «Все»↔«Избранное» `heapMb`/
`heapAfterGcMb` без устойчивого роста (дисперсия в пределах единиц–нескольких МБ),
время переключения не деградирует; Linux без регрессий; подтверждение автора.

**Инструктирование автора (7OH):** включить диагностику `CM_TREESWITCH` (и
`CM_TREESWITCH_FLUSH` для сравнения) — trace.json / env `CM_TREESWITCH=1`; в логе
контролировать поля `heapMb`, `heapAfterGcMb`, `collReset`, `resetMode`, `rowsRealized`,
`rowsCleared`, `detachCount` (счётчик отписок узлов), `flushPanels`.

- [ ] **Windows (WPF):** 30 переключений «Все»↔«Избранное» → `heapMb`/`heapAfterGcMb`
      без устойчивого роста (дисперсия в пределах единиц–нескольких МБ).
- [ ] **Windows (WPF):** время переключения не деградирует к 30-му переходу.
- [ ] **Windows (WPF):** `collReset` — не более 1 на переход, без «шквала» поштучных
      событий; `rowsRealized` не растёт с каждым переходом.
- [ ] **Windows (WPF):** `detachCount` в логе CM_TREESWITCH подтверждает отписки узлов
      (счётчик растёт при смене вкладки).
- [ ] **Windows (WPF):** GCDump после 30 переключений не показывает живых «старых»
      строк/контейнеров от прошлых вкладок (по `_issue21_gcdump_instructions.md`).
- [ ] **Linux (Avalonia):** поведение и производительность не изменились (или улучшились).
- [ ] Комментарий автора в issue #21 с подтверждением замеров (логи CM_TREESWITCH).

## Issue #25 — Импорт из кластера 1С (1.0.0.42)

**Критерий готовности:** «Подключиться» на 8.5.1 не показывает ложную ошибку; единственный
кластер выбирается автоматически; список баз показывается сразу (оба входа).

**Инструктирование автора (7OH):** при воспроизведении включить диагностику
`CM_CLUSTERIMPORT` (trace.json / env `CM_CLUSTERIMPORT=1`) — фазы Connect/LoadBases,
автовыбор, повторные попытки, ошибки с типом исключения.

- [ ] **Windows (WPF):** «Утилиты → Импорт из кластера 1С» → сервер с **одним** кластером →
      «Подключиться» → без промежуточной ошибки сразу: кластер выбран автоматически,
      показан чеклист баз.
- [ ] **Windows (WPF):** сервер с **несколькими** кластерами → подсказка «выберите кластер»;
      ручной выбор кластера → список баз загружается.
- [ ] **Windows (WPF):** вход из окна «Серверы 1С» с переданным кластером → приоритет
      переданного кластера, список баз сразу.
- [ ] **Windows (WPF):** первая попытка загрузки при непрогретом формате rac повторяется
      без показа ошибки; после успеха `ErrorMessage` пуст, статус «Загружено».
- [ ] **Linux (Avalonia):** те же проверки (один/несколько кластеров, оба входа окна).
- [ ] Комментарий автора в issue #25 с подтверждением сценария (лог CM_CLUSTERIMPORT).
